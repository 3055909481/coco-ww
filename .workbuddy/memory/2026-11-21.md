## 运行时 NameError 热修复（v1.0.6）

用户实机报 `NameError: name '_obf62' is not defined`（BaseCombatTask._oldest_switch_target 的 lambda）。

根因：obfuscate.py 的 visit_Name 从内到外穿透查找 scope。源码 `chars=[c for c in chars...]; min(chars,key=lambda c:...)` 里，外层推导变量 char 被改名 _obf62，而 lambda 参数 char（独立 scope，未改名）被错误穿透到外层映射，lambda 体变成 _obf62.xxx → 未定义。附带发现第二个 bug：函数体对参数重新赋值会把参数名也改掉，破坏关键字调用。

修复（一次性）：
- _Scope 增加 bound 集合（参数+局部变量），visit_Name 只认最近的绑定层，未改名的参数也挡住外层穿透
- 参数名（函数/lambda）绝不进 mapping，即使函数体重新赋值
- 补 2 个回归测试；全量 103 源码 symtable 扫描 + 真实函数端到端验证

发版：bump v1.0.5→v1.0.6（push config.py 自动触发 CI），run 44893159670 success。Release v1.0.6 挂 zip(315.5MB)+清单；从 obfuscated 分支拿 pyc 反编译确认 lambda 无 _obf 引用。

教训：AST 重命名的作用域处理必须用"绑定层"而非"映射层"判断，参数即使不改名也是绑定，必须阻断向外穿透。lambda/嵌套函数与外层同名局部变量是高危场景，回归测试必须覆盖。

## 彻底根除 _obfN NameError（v1.0.8，最终）

用户实机再次报 `NameError: name '_obf70' is not defined`，在 BaseCombatTask._lowest_buff_remaining_target 的 lambda。这是第二次同类事故（v1.0.6 _obf62、v1.0.7 _obf70），确认手写 AST 作用域跟踪不可靠，**改为架构决策：彻底移除局部变量重命名**。

根因（v1.0.7 这次）：`buffers=[char for char in candidates ...]` + `lambda char: self._buff_remaining(char)`。Collector 把推导式变量 char 当外层局部变量收集并改名 _obf70，但推导式在 Python 3 是独立作用域，lambda 参数 char 未改名却被穿透替换 → lambda 里引用不存在的 _obf70。另有 `_collect` 里 self.visit() 误用 Renamer.visit 的隐患，以及 walrus/match/except-as 未覆盖。

决策依据：pyc 的 co_varnames 本就明文存所有变量名，反编译器直接可读，局部变量重命名防护收益近零；两次生产事故证明风险远大于收益。真正有效的防护（无明文 .py、去 docstring/注释、字符串编码、AST 重排）全部保留。

实现：
- tools/obfuscate.py 删除 _LocalRenamer/_Scope/_all_arg_nodes/_arg_expressions 及 rename_locals 参数，模块顶部写明"永久不改名"的决策理由（防止后续"优化"回来）
- tests 新增 test_no_identifier_is_ever_renamed（全部 103 源码强制校验：无 _obfN + 原始标识符集合是混淆后的子集）、test_historical_nameerror_cases（v1.0.6/v1.0.7 真实代码形状）
- docs 同步说明
- bump v1.0.7 → v1.0.8，push 自动触发 CI，run 44895146074 success

验证：20 项混淆测试 + 6 项更新 + 3 项降级全过；本地构建 106 个 pyc 扫描 _obfN 零残留；发布版 raw 下载 BaseCombatTask/BaseChar/AutoCombatTask.pyc 均无 _obf；整包 315.4MB 无明文 .py。

教训（长期）：AST 改名类混淆在 Python 动态作用域面前是高风险低收益，本项目永久禁用。回归测试用"零改名"做结构性保证，而非逐个 bug 补案例。

## 更新失败（CDN 中文路径）修复（v1.0.9）

修复（一次性）：
- release_manifest.py 新增 MANIFEST_EXCLUDE_PREFIXES=("docs/",) 和 MANIFEST_EXCLUDE_SUFFIXES=(".bat",)，清单排除这些文件（整包 zip 里都有，不需在线更新）。清单文件数 1128→1124，非 ASCII 路径归零。
- pyappify 新增 LOCAL_ONLY_FILES/LOCAL_ONLY_PREFIXES 与 _is_local_only()，plan_update 的下载与删除循环都跳过它们。**关键**：不跳过删除的话，老用户清单→新清单会把本地 bat 当作"新版删掉的文件"删除，导致无法启动。
- 更新 test_online_update.py 期望（bat 不进 replace/删除、回滚重试改为下载 src/added/new.py），新增 test_local_only_bat_and_docs_not_deleted；test_obfuscation 新增清单零非 ASCII 路径断言。

教训：在线更新清单里绝不能放中文路径文件——多下载源（尤其 CDN 镜像）对非 ASCII 路径支持不一。文档和启动入口这类"整包自带、很少变"的文件应从清单排除，同时更新器要对它们做本地保留（下载+删除都跳过）。
